## Proposed thesis evaluation plan — requires adviser approval

### Population, inputs and comparison design

Freeze an accepted IT year/term cohort including zero-assignment members, the full required offering/component multiset, exact room/person/section mappings, target/eligibility/profile revisions, applicable preferences and complete confirmed external/availability snapshots. Outside faculty/resources can be dependencies without joining an unverified IS optimization population. Treat input invalidity, missing authority, an actual hard violation and search-budget exhaustion as different outcomes.

Compare the supported baseline and each **separately approved** candidate release on the same frozen feasible problem definition, paired preregistered seeds and a declared common budget. Choose whether budget means generations, candidate evaluations or wall time before interpreting cost/quality. Report different budgets honestly. Preserve all variants and trials; do not select only good seeds or count a zero-start score as convergence. Strategy or policy changes can alter subsequent RNG trajectories even with paired seeds.

Use fictional data for protocol calibration. If real data are later authorised, separate tuning/calibration from the final confirmatory dataset/runs and document any unavoidable reuse. Preregister repetitions/sample-size rationale, primary/secondary outcomes, meaningful effect thresholds, handling of ties/multiplicity and uncertainty analysis. No arbitrary repeat count or institutional quality threshold is approved by R1.
