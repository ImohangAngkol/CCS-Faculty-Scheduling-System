## Implemented execution boundary

The opt-in app factory `routers.research_operator.create_app` is never registered in ordinary `main.py`. It requires the existing fictional-source guard and an explicitly constructed server permit, J authority/input source, I private owned store, K lease/fence and L process identity/Job policy. Missing configuration returns 503 before opening any ordinary identity database. Administrator role alone grants no scoped research or Chair authority.

The separate `/research/operator` HTML/module uses real session authentication, server-side scoped authorization and Origin/CSRF enforcement. Start accepts a request UUID only; client departments, roles, limits, bundles and fitness are rejected. Limits are server-owned: at most two total generations, one generation per original worker batch and a 60-second run wall bound, within the unchanged 600-second ceiling. A fixture/configuration can finish sooner. The existing physical child limits remain 768 MiB private commit and 60 seconds user CPU. A five-minute admission window is durably bound to the permit and cannot be extended by reconstructing the adapter. Stop remains available after that window.

Only Start and cooperative Stop are operational. There is no Pause, Resume, active Restore, Saved Best promotion or institutional worker activation. URL request/run UUIDs are lookup identities, not authority. Reload revalidates the real session and never starts execution. The console includes explicit fictional warnings and read-only observation links. Imported/runtime strings render through text content; passwords are cleared from fields immediately after submission, never persisted in browser storage or evidence. This is not a claim of secure memory zeroization.

### Admission, audit and acknowledgements

The adapter creates three auxiliary tables only in a new empty, privately owned fictional SQLite store. Signed metadata binds the permit, limits, expiry and audit head/count. Every admitted control request has a bounded authenticated REQUEST-to-ACK/FAILED chain; the current request pointer must match the append history. Missing/tampered metadata, event deletion, mismatched binding and audit exhaustion fail closed. Original I admission idempotency and K/L exclusive execution ownership remain authoritative. Concurrent calls use bounded adapter/bridge locks; an active or uncertain executor prevents another Start.

An ACK is recorded only after the original operation and response projection succeed. A dispatched action cannot be undone by a later response/audit write failure. REQUEST or FAILED therefore remains indeterminate and is never automatically dispatched again. Authentication/CSRF denials happen before authorized control execution and have HTTP denial evidence, not fabricated successful lifecycle events. The private audit is authenticated against local alteration; it is not an external anti-rollback service or institutional approval ledger.

All new adapter reads use the bounded bridge lock and acquire current authority/source guards **before** the existing read-only SQLite snapshot. This matches the worker heartbeat's authority-to-source-to-SQLite order. The original observation snapshot opens SQLite before entering those guards; invoking it concurrently with source-held admission can create an inverse lock dependency. The new wrapper preserves every original verification and the DELETE journal policy while ordering its calls safely. The negative regression proves request inspection cannot open a read snapshot while admission owns the bridge lock; the mapping test also asserts authority/source scopes are already established on entering the original snapshot. A new Start is rejected while a prior owned supervisor is still alive, including its final observation phase after executor release.

Start acknowledgements can be lost or delayed independently of execution. A scoped, read-only `/api/research/operator/requests/{request}` lookup resolves the original run mapping without admitting, restoring or relaunching it. The UI offers **Inspect request** and may attempt that read after a failed acknowledgement; execution itself is never automatically retried. Missing and cross-owner mappings fail closed. Tests verify pending mappings remain pending and lookup changes no store bytes. The request UUID is preserved across explicit retries/reloads.

### Stop and observation truthfulness

The original worker command is cooperative. Stop during a batch or checkpoint publication can report STOPPING and **termination not verified**. STOPPED/result confirmation requires the original durable event/tip/fence, released executor/lease, verified child exits and full v2 read-only provenance projection. A repeated Stop or acknowledged Start replay reads the existing run; it does not create a new supervisor. A test-owned unrelated sentinel process remains alive after Stop.

Full observation reconstructs and validates chromosomes. Doing that inside every active control response can delay the original heartbeat and hide the short active-work window. The new adapter returns cheap, scoped lifecycle metadata during execution, with `fitness: null` and `FULL_READ_ONLY_PROJECTION_REQUIRED`. It does not invent a fitness observation. Only after cleanup does the original complete projection expose results, preserving exact zero. The four existing observation route implementations remain GET-only and unchanged. The isolated host supplies an adapter that defers expensive listing/detail/telemetry with 503 while any executor exists, holding the same bridge lock across its idle/read check. Ordinary observation providers are unchanged.

Add deployment-independent health/ownership diagnostics and specify expiry, failure and operator escalation procedures before considering any operational service. Preserve CPU quota-overrun uncertainty until separately investigated. Do not enable institutional execution, increase duration or activate recovery as part of that recommendation.
