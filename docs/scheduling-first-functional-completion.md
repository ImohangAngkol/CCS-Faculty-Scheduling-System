## Contracts proposed before implementation

**Minimum policy:** server-owned scope (department, academic year, term, captured bundle identity), immutable integer revision, parent digest, actor and timestamp. A sparse per-faculty map contains only explicitly configured `minimum_teaching_units` values; absence means unspecified, not24. Soft targets and hard maxima remain captured read-only model observations. Minimum may be above a soft target; expose that distinction instead of silently changing original scoring inputs. Reject negative/nonintegral/boolean/over-ceiling/unknown-faculty/duplicate fields. The first implementation supports the original integer-unit model; fractional-unit policy is not invented.

**Qualification:** derive per-faculty eligible-unit upper bounds from the supplied immutable bundle's normal, non-preassigned offerings. Report each minimum and upper-bound shortfall before any optimizer call. Sufficient units mean only `NOT_PROVEN_INFEASIBLE`, not feasibility. Post-result assessment recomputes assigned units once per offering and reports `MINIMUM_WORKLOAD_VIOLATION` for every explicit deficit, including zero-assignment roster members. It supplements, never replaces, existing eligibility/resource/completeness validation. It does not alter fitness or silently discard invalid candidates.

**Weight model (proposal only):** immutable policy ID/version/digest, scoped authorized editor/activation action, actor/time, original scorer version/fingerprint, all exact GASetting values and previous-policy reference. Freeze the complete setting map with each run and bind it to comparison/checkpoint/Saved Best context. Faculty can read the relevant policy; private presets, if added, are isolated experiments with distinct contexts. Generic admin role does not grant department-wide activation. Original supported components are subject/time/day preference, schedule style, lecture/laboratory arrangement, preparation count, teaching-load bands and daily teaching time. Their existing penalties/importance/priority application must be preserved; a weight is not a normalized satisfaction percentage. Specialization is not an existing scoring component. No new mathematical term, normalization or scorer dispatch is implemented here.
