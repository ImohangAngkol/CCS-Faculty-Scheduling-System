## Trusted context and comparability

`ResearchPermit` is an internal, frozen server object: exact actor UUID, department UUID, catalog, reviewed prepared-bundle fingerprint and explicitly fictional academic year/term/dataset labels. HTTP callers cannot supply a permit, role, department, bundle, context, scoring settings or fitness. Admission accepts only an idempotency UUID. A request label or matching hash alone is never authority.

Both the existing independently scoped J mandate and guarded J prepared-source adapter remain required. The bridge additionally checks its reviewed prepared-bundle fingerprint on every lifecycle operation and heartbeat. An input/source change, revocation or unverifiable provenance fails closed. Fictionality is established by the deliberately constructed D10/J test corpus and explicit server allowlist, not by a universal detector of fictional names. No institutional catalog is automatically admitted.

Context is derived from the actual I-admitted immutable G bundle and H materialization: faculty/eligibility/loads, subjects, sections, rooms, availability calendars/time blocks, legacy preferences, scoring preferences/settings, seed inputs, configuration, source engine and optimizer identity. It retains academic scope, exact bundle/loaded-model fingerprints and configuration provenance. Fitness remains original minimization; exact zero and ties are preserved.

The complete evaluation-graph fingerprint excludes only search configuration. Thus run UUIDs, capture timestamps, seeds/search horizons are not blindly treated as objective identity. Exact bundle/configuration provenance remains available; cross-capture numeric comparison requires a guarded proof that the complete materialized evaluation inputs are equal. Order, aliases, seed content, calendars, eligibility and all other captured graph content remain in that conservative projection. False mismatches can decline comparison; unknown inputs are never silently declared equivalent.

| Finding | Treatment |
|---|---|
| Admitted but no committed worker consumption | UNVERIFIED_NOT_CONSUMED |
| Exact consumed inputs, original receipt and committed checkpoint/result bindings | TRUSTED_FICTIONAL_CONSUMPTION only |
| Known differing semantic contexts | U5P-A comparison returns INCOMPATIBLE, no scalar ranking |
| Unknown/unattested legacy archive | UNVERIFIED; retain exact bytes |
| Missing context/proof/checkpoint | Explicit MISSING/UNVERIFIED rejection code |
| Changed binding, malformed record or bad authentication tag | Explicit CHANGED/MALFORMED/TAMPERED rejection code |

The new verifier signs only the server-reconstructed candidate from a qualified result; a caller cannot submit arbitrary fitness/content for attestation. The research best path is fixed inside the new owned store (`RESEARCH-BEST.json`). U5P-A's default production verifier remains None. Institutional Saved Best is never read, migrated or overwritten. Unknown research archives also decline replacement; there is no automatic historical qualification.

## Original worker and consumption boundary

The execution chain is:

```text
authenticated principal + explicit server research permit
  -> unchanged J mandate/source verification
  -> unchanged I run UUID/idempotent admission + immutable bundle/private RNG
  -> original K bounded batch loop + L creation-time Windows Job supervision
  -> unchanged child protocol + H optimizer/original GA function bodies
  -> new receipt-observation adapter
  -> unchanged K checkpoint/projection validation and atomic durable tip
  -> qualified research telemetry/result comparison
```

Inspection found that the child already emits a technical consumption receipt, but the original parent does not retain that receipt. `ResearchWorker._exchange` invokes the unchanged L implementation, waits for its real child cleanup, and verifies the receipt against the exact admitted or resumed templates, preferences, scoring context, configuration and private RNG entry. Run/bundle/loaded-model/optimizer/configuration/checkpoint identities and original function-call evidence must match. A forged loaded-model receipt is rejected before a checkpoint is accepted.

The new signed proof can be written before K commits a checkpoint; that proof alone is insufficient. Qualification requires its exact committed checkpoint lineage, inner hash, result digest and original K/L ownership/physical-policy pins. `qualified_result` also performs original H checkpoint decoding/validation and stop-before-next-draw finalization to compare the resulting schedule, score, breakdown, history and faculty analysis. It does not restart the search or alter the RNG trajectory. Missing, changed or orphaned proofs do not become successful runs.

No generation loop, fitness function, chromosome representation, operator or stopping rule was replaced. The subclass adds scoped checks and observations around the existing worker. Extra verification has overhead and can consume an existing wall budget; it does not increase that budget. Scale/performance qualification is not claimed.

## Durable telemetry and storage guarantees

New research tables are created only in a newly owned U5L disposable SQLite store. Existing identity/workflow/GA databases and migration files are untouched. Reopening requires the same store identity, new-contract release bytes, permit and key. No path or database URL is accepted from HTTP clients.

Contexts and consumption proofs are HMAC-bound to the store/release. Telemetry has per-run sequence numbers, previous hashes, payload hashes and authentication tags, plus an authenticated count/head anchor. Tests reject changed payloads, missing context, tail deletion, reordering, cross-run proof reuse, key corruption and partial transaction writes. The key stays inside the ACL-private owned root and is not printed or archived.

The underlying synchronous SQLite transactions, page limit, free-space checks and atomic original checkpoint/event updates remain in force. Concurrent readers observe committed transactions. A final callback normally records terminal observations even without a client poll. If a callback cannot commit, original worker events and checkpoint state remain durable; an explicit observation failure is retained, and a later authorized read may backfill from those events. A full ledger rejects writes rather than deleting history or returning a fabricated success.

| Field | Evidence classification |
|---|---|
| Run/context ID, original worker state/reason, checkpoint reference, source-event timestamp | Observed from bound durable worker records |
| Generation and best-so-far fitness | Observed at committed batch/checkpoint boundaries; exact zero retained |
| Elapsed wall seconds | Derived from worker event time minus admission time, including queue/verification time; not isolated GA search timing |
| Current fitness | UNAVAILABLE_NOT_EXPOSED; no invented population statistic |
| Satisfaction metrics | UNAVAILABLE_NOT_EMITTED; no inferred preference percentages |
| Expired ownership/interruption/orphan state | Derived from lease and PID-plus-creation-time liveness; timestamped and labeled |

There is no promise of an observation for every generation when batches span multiple generations. Existing worker result histories remain available to the internal result contract; the new HTTP API exposes state and bounded observations, not a new graphical analysis console.

Retention is bounded and nondestructive: maximum 256 events of at most 8 KiB per run, at most 21 receipt proofs of at most 8 KiB, the existing four-run fixture store, unchanged checkpoint limits, and U5L's 64 MiB main-database cap. Retention exhaustion rejects new work/observations; it does not purge evidence. The existing Saved Best policy independently bounds the separate research-best file. SQLite journals/backups/temporary files and host-wide disk/RAM are not covered by a filesystem quota.

Authentication tags address accidental corruption, partial writes and unauthenticated edits within the private-store threat model. They are not a hardware trust root and do not resist a malicious OS owner or replay of all trusted storage/key state. Deployment-wide anti-rollback, independent freshness anchors and distributed custody remain unqualified.

## Lifecycle, ownership and recovery

Creation is idempotent through original I/K keys and SQLite serialization. Original ownership fences and named Windows Jobs prevent duplicate active ownership; the bridge never uses a client role as a grant. It exposes start/status/telemetry/stop and research-best comparison only.

CREATED/RUNNING/COMPLETED/STOPPED/FAILED retain original conventions. Known `GA_WORKER_TIME_BUDGET` failures are derived as RESOURCE_LIMITED; an unexplained child crash remains FAILED rather than being attributed to CPU or memory. An expired owner with a matching live process becomes RECOVERY_REQUIRED; with no live matching process it becomes INTERRUPTED. API/service reconstruction cannot convert either condition into successful completion or automatically reclaim ownership.

Stop remains an original bounded-worker command; repeated created/terminal stop does not invent a checkpoint or best result. Completed start is idempotent. Interrupted, failed and resource-limited runs cannot be restarted through this bridge. Pause/resume and active restore routes are absent, including attempts to bypass quarantine through an action path. Original U5N independent recovery/quarantine contracts and historical artifacts remain unchanged.

HTTP account/session validity and CSRF are checked for each request through the existing real authentication dependency. Background execution separately rechecks the independent optimization mandate and prepared source, not a browser session's continued lifetime. Revocation coupling for a future institutional service requires an explicit service-identity policy; no institutional policy is invented here.
