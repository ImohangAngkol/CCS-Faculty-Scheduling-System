An experiment is a one-to-one, versioned UUIDv5 projection of the durable owned-store/run identity. Its backing records are the original runs, immutable bundle, checkpoint chain, signed context/proofs/events and E control audit. No new experiment table is necessary. Reconstruction must produce the same identity. This is durable ledger-backed projection, not a newly persisted experiment document or external attestation.

One server-bound fictional context is available per isolated host. UI selection acknowledges that context; it cannot supply or change scope, bundle or authority. Original E controls still perform every server-side check. Reads preserve E's bridge -> authority -> source -> SQLite ordering. Active monitoring exposes recorded checkpoint generation and lifecycle only, without claiming validated fitness. Complete export requires independently confirmed terminal cleanup, a final signed ledger observation and the original reader's context/checkpoint/proof validation. GET never backfills observations or writes stores. Interrupted, pending or corrupt records do not become verified exports.

JSON, CSV and plain-text exports use closed scalar projections, strict bounds and no-store headers. They include context/engine/configuration fingerprints, source classification and a canonical-record SHA-256. The digest identifies content; it is not a signature, authority grant or proof against a malicious store owner. No faculty/subject/room records, preferences, credentials, receipt signatures, private RNG state or checkpoint payloads are exported. The original coordinator generates private initial RNG state independently of the bundle's schedule-baseline seed: public exports do not establish exact replay from a seed.

Initial fitness must come from a signed, bound generation-zero checkpoint proof. Original result-history rows remain distinct from checkpoint samples and are never filled in. Improvement is initial minus final only within that bound context; percentage is unavailable for zero/negative initial values. Actual generation count comes from the validated result, never the number of rows. Preference satisfaction and explicit hard-conflict counts remain unavailable when not recorded. Existing fitness breakdown is labeled soft-penalty components, not hard-constraint counts.

Export caps: 256 KiB JSON, 128 KiB CSV/text, at most 256 observations; no partial output on overflow. Original E limits remain unchanged (two total generations maximum, 60-second run budget under the existing 600-second ceiling, original physical policy). Technical short-run demonstration is separate from statistical thesis evaluation and institutional approval. Manual human handoff is not claimed unless actually performed.
