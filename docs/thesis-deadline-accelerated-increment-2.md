## Frozen input execution path

The separate loopback factory `routers.prototype_cycle.create_app(cycle, identity_db)` composes the existing input desk and the new review/observation API. Ordinary `main.py`, fixed-generation endpoints, institutional authority and Saved Best are unchanged. With no configured service/database it fails closed. There is **no HTTP execution, step, resume or recovery endpoint**.

1. An authenticated, explicitly scoped scheduler selects an existing immutable preparation. `Cycle.admit` reads its exact canonical bundle bytes through the existing `Inputs.prepared` validator, captures its original minimum/weight/preference provenance, and verifies its resource profile equals the trusted source catalog. It accepts a preparation ID and nonce, not a client score, seed, role, bundle or arbitrary configuration.
2. The current finite admission profile retains generation ≤20 and population ≤8. The input's original parameters remain unchanged. The legacy priority frame must have exactly the model cohort, unique IDs and finite positive integer priorities. Missing preference submissions remain optional; missing required **legacy priority metadata** rejects the whole input instead of dropping faculty or inventing their priorities.
3. Individual eligible-unit upper bounds are compared with the captured sparse minima. The 24-minimum/12-eligible case is persisted as `INPUT_INFEASIBLE` with shortage 12 and no GA execution. Individual bounds do not prove joint feasibility; a deliberately jointly impossible case verifies that a genuinely generated deficit cannot be approved. No new search-time admission, repair or scoring term is introduced.
4. Qualified offline tests explicitly enable `step_offline` in an owned empty-import source snapshot. It calls the existing `ga_bundle_optimizer.Session` with the **exact frozen bundle**, private initial RNG state and original versioned runtime. Initialization, selection, crossover, mutation, fitness and constraints are original code. The default constructor disables this oracle, and HTTP cannot enable or invoke it. It is not a replacement for Windows process supervision or a way around native acceptance gates.
5. At an original generation boundary, the original cooperative Pause saves a full original checkpoint. Projection uses the same original `Session.restore` and Stop-before-next-draw technique already used by `ga_worker_child`: real assignments, fitness, breakdown, per-faculty analysis and complete original history are produced without advancing RNG. The controller checks best/history/generation consistency and retains the original consumption receipt.
6. The candidate is reconstructed from those assignments and checked by the original publication validator plus the existing captured-minimum assessor. Normal GA-managed credit units are counted once per offering; external/preassigned commitments retain the earlier explicit exclusion. An unmet minimum makes the candidate not fully feasible, regardless of its original fitness. Candidates are retained, never repaired, filtered into a different schedule or relabeled as valid.
7. Actual bundle/configuration/optimizer/scoring identities, checkpoint sequence/parent, original RNG fingerprint, original results and qualification are durably committed. Raw bundles, RNG states, checkpoints and witness keys remain only in newly owned temporary stores, not repository evidence or public exports.

Logical experiment IDs and the optimizer's frozen-bundle run ID are explicitly distinct; both are recorded. The outer checkpoint chain binds the logical run, owner, source, segment and witness, and rejects cross-run grafting. This is not permission to rebind an inner original checkpoint or reuse an offline checkpoint in a new native admission. A future native adapter must establish its original server-owned run/bundle identity once and restore only that identity, without migration or fingerprint spoofing.

## Implemented continuation architecture and honest limits

`Cycle` is a separate `fictional-scheduling-continuation-v1` coordinator using new SQLite files and the original checkpoint codec. `TipWitness` is a separate durable HMAC-chained journal in another new owned directory. Reopen requires the owner's pinned key fingerprint; raw keys never enter evidence. All writes are atomic within each SQLite transaction and immutable checkpoint/review/version rows reject UPDATE/DELETE. Storage is checked before committing payloads; quotas reject rather than delete or truncate history.

Implemented/tested: stable frozen inputs, original full population/generation/working-template state, original scoring context, private initial RNG plus resumed RNG, original best-ever/history, checkpoint hashes/parents, private durable results, nonce idempotency, exclusive executor leases/fences, cooperative Stop requests, recovery from a logically interrupted expired lease, source/version checks before resume, corruption rejection, primary-store rollback rejection, cross-run graft rejection, context-safe comparisons and real exports.

The segmented and uninterrupted **same** logical optimization result agrees exactly on assignments, fitness, breakdown, history, faculty analysis and final RNG. Reconstructing the coordinator and witness objects from their actual files resumes the same checkpoint; it does not reseed or start a fresh experiment. The original checkpoint already contains the necessary GA state. No mathematical/RNG extension or missing-GA-state workaround was needed.

Explicit limits:

- **Finite profile only:** a 600-second original-style lifetime ceiling, 60-second cooperative offline segment checks, at most eight retained segments, 8 MiB checkpoint cap, 64 MiB stored-content budget and conservative database-size limit. The synchronous oracle checks elapsed time at boundaries/return; it does **not** provide an OS kill, CPU or RAM guarantee. Existing native L supervision and its general 600-second guard are unchanged. Offline execution is additionally restricted to ≤2 configured generations.
- **No native termination claim:** a returned synchronous call is not a verified Windows worker exit. Stop acknowledgements explicitly say termination is unverified. No native worker was launched, killed, restored or deployed.
- **No actual process/power crash acceptance:** tests reconstruct objects and the listener, simulate expired ownership, corrupt or roll back only newly created disposable stores, and inject witness failure. They do not prove OS-process death, host restart, power-loss durability, surviving helper-process cleanup or operating-system resource enforcement.
- **Two-store uncertainty is quarantined:** if the primary checkpoint commit succeeds but advancing the separate witness fails, the checkpoint is retained, failure is recorded and resume/read fails closed against the mismatched witness. It does not auto-advance the witness or discard/recompute history. A separately authorized reconciliation protocol remains required. Primary errors are preserved; audit-write failure is tracked separately in memory if durable reporting is itself unavailable.
- **Local witness is not deployment identity:** HMAC/key-pin verification and primary-store rollback detection do not authenticate an entire host or detect rollback of the primary, witness and key together. No ACL was changed or claimed qualified. An independently trusted freshness/ownership anchor, confidential key custody and approved backup/recovery policy remain required for deployment.
- **Cold-start bootstrap is not yet independently exercised:** the run's frozen bundle, RNG, checkpoint and results are persisted. A real process restart still needs trusted source/catalog/identity provider reconstruction, root/key/tip pins and the original input-service bootstrap. Current listener tests deliberately retain the configured input service; they are not a cold-start acceptance pass. Never reconstruct authority or fingerprints from untrusted stored labels alone.
- **Not a long-run admission release:** current generation, lifetime, storage, witness and transport caps are deliberate. Neither this foundation nor a loop around the existing E/K worker can run 168 hours. Long histories/complete checkpoint graphs must be measured before an approved new retention/archival contract; do not prune engine state or raise limits silently.

To reach a seven-day release, approve a separately versioned experiment policy that fixes its generation horizon and original stopping behavior before capture, separates the 168-hour experiment clock from **physically enforced ≤600-second segments**, preserves the exact logical run/bundle/RNG, defines externally anchored ownership/freshness and uncertain-commit recovery, and provisions immutable archives within measured storage limits. Keep the old finite admission/checkpoint contracts valid and unchanged. Checkpoint parameters cannot be enlarged after resume. If the original GA finishes early, record that; independent fresh runs are a different research campaign, not continuous optimization.
