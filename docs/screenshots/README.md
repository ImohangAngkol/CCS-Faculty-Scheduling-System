# Actual browser screenshots

New captures belong under `<phase>/<unique-run-id>/`. Keep existing `admin-dashboard.png` and `generate-schedule.png` in place; their original capture provenance is not re-established by the new evidence run.

Use actual rendered browser screenshots and inspect them before inclusion. Capture only synthetic/test accounts and nonprivate content; never include passwords, tokens, cookies, developer-tool network headers or institutional faculty records. Do not generate or fabricate screenshots, change DOM content to manufacture a success, or relabel an old image as a new capture.

Each image must have a scenario ID, description, timestamp, browser/window information and SHA-256 recorded in the corresponding testing manifest. Cite screenshots from a phase evidence report and state their limits: UI appearance alone does not prove backend security or GA correctness.
